服务器使用Codex

引言

在远程 Linux 服务器上使用 Codex，通常有两种方式：

  • Codex 运行在本地，通过 SSH 操作服务器：例如在 Windows 上启动 Codex，让它执行 ssh 命令查看 GPU 状态、运行脚本或修改远程文件。这种方式不要求服务器安装 Codex，也无需服务器直接访问 OpenAI。不过，Codex 的工作目录仍在本地；读取大量远程代码、跨文件搜索和修改时需要不断通过 SSH 执行命令，文件路径、运行环境和权限也更容易混淆。
  • Codex 直接运行在服务器上：在 Linux 上安装 Codex CLI，或通过 Windows Codex Desktop 的 Remote SSH 功能连接远程项目。此时 Codex 直接读取服务器文件、调用服务器上的工具和环境，更适合持续开发、调试和重构。
    本文采用第二种方式：让 Codex 在服务器上执行实际工作，并使用 Windows Codex Desktop 作为主要操作入口。同时保留在服务器终端直接运行 codex 的方式，方便排查问题。

本文以 Windows 本地电脑、Ubuntu 22.04 共享服务器为例。服务器使用普通用户账号，没有 sudo 权限；Windows 上已有提供 HTTP/Mixed 端口的代理软件。文中的主机名、用户名、端口和项目目录均为示例，需要根据实际环境修改。

疑难问题

以下是实际使用中可能遇到的问题。

CLI 已升级，但 Desktop 仍显示旧模型

通常来说如果codex desktop连接远程服务器，但是模型列表却显示旧模型，可能是服务器端codex cli版本过低导致，因为codex desktop的远程底层逻辑是使用codex cli来完成的，所以需要升级codex cli然后重新连接远程运行。可能此时会发现使用vscode远程连接服务器，然后通过插件使用codex时模型列表显示正常，这是因为vscode和codex desktop的远程顶层逻辑不同导致的。如果codex cli已经升级但是，但是模型列表仍然不更新则可尝试以下方法。
