MoE理论学习

部分内容由AI生成

1. 引言：MoE 想解决什么问题

MoE（Mixture of Experts，混合专家）的核心并不复杂：模型内部准备多组可以独立工作的子网络，但每次只根据输入选择其中一部分参与计算。它最初强调的是“专家分工”，后来随着模型规模不断扩大，这种结构又被用来解决另一个更现实的问题——如何增加模型的参数容量，同时避免单次计算量与总参数量同步增长。

以 Transformer 为例，一个 Block 可以粗略理解为 Attention 加 FFN。Attention 负责 token 之间的信息交互，FFN 则对每个 token 的表示做进一步变换。对于 Dense Transformer，所有 token 都经过同一个 FFN，因此当我们不断增加 FFN 宽度或层数时，模型参数量和每次前向传播的计算量通常会一起增长。MoE 的思路是把原来的一个 FFN 换成多个 Expert，再使用 Router 为不同 token 选择不同 Expert。

这里最重要的变化不是“FFN 数量变多”本身，而是不同输入不必使用所有 FFN。因此 MoE 可以看作一种 Conditional Computation（条件计算）：模型拥有一个较大的参数池，但每次只调用其中的一部分参数。

如果只从大模型 Scaling 的角度看，可以把它概括为：Dense 模型中，总参数量增加通常意味着每次计算量也增加；MoE 则试图让两者部分解耦，使模型可以拥有更大的参数容量，而单个 token 的计算量主要由被选中的少数 Expert 决定。

2. 基础原理：Expert、Router 与稀疏计算

2.1 Expert 是什么

经典 MoE 中的 Expert 通常并不是什么特殊网络，它本质上就是一个独立的 FFN。普通 Transformer 的 FFN 可以写成 $FFN(x)=W_2\sigma(W_1x)$，其中 $x$ 是 token 的 hidden state，$W_1$ 和 $W_2$ 是两层线性变换的参数，$\sigma$ 则可以是 GELU、SiLU 等非线性函数。

MoE 将一个 FFN 扩展成多个独立 FFN：

$$
E_1(x),E_2(x),\dots,E_N(x)
$$

每个 Expert 都有自己的一套参数。例如 $E_1$ 和 $E_2$ 虽然结构相同，但它们的 $W_1$、$W_2$ 并不共享。正因为参数彼此独立，它们在训练过程中才有机会逐渐学习不同的数据模式。

2.2 Router 如何选择 Expert

有了多个 Expert 后，需要一个模块决定当前 token 应该交给谁处理，这个模块就是 Router，也常被称为 Gate。最简单的 Router 可以只是一个线性层。假设 token 的 hidden state 为 $x\in\mathbb{R}^d$，共有 $N$ 个 Expert，则可以计算：

$$
z=W_rx,\qquad W_r\in\mathbb{R}^{N\times d}
$$

再对 $z$ 做 softmax，得到每个 Expert 的路由概率：

$$
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}}
$$

2.3 “一个 token 不经过所有 Expert”到底是什么意思

“经过某个 Expert”从实际运算角度看，就是让这个 token 的向量与该 Expert 的权重发生矩阵乘法。假设第 $i$ 个 Expert 为 $E_i(x)=W_{2,i}\sigma(W_{1,i}x)$，而 Router 最终只选择了 Expert 2，那么实际执行的是：

$$
E_2(x)=W_{2,2}\sigma(W_{1,2}x)
$$

其他 Expert 对这个 token 根本不会执行前向计算。因此“没有经过 Expert 1”并不是一种抽象说法，而是程序里根本没有调用 expert_1(x)，相应参数也没有参与该 token 的矩阵运算。

这也是 Total Parameters 与 Active Parameters 的区别。假设一个模型总共有 100B 参数，但某个 token 的前向传播只实际使用了 20B 参数，那么可以说模型有 100B Total Parameters、20B Active Parameters。这里的“激活参数”并不是说参数被打开或关闭，而只是表示当前 forward 中真正参与计算的参数。

2.4 Dense 与 Sparse

MoE 中的“稀疏”主要指计算路径稀疏，而不是参数矩阵里有大量 0。一个 Expert 自身完全可以是普通的 Dense FFN，只是对于某个 token 来说，大多数 Expert 不会被调用。

如果一共有 $N$ 个 Expert，而每个 token 只选择 $K$ 个，那么从 Expert 层面看，某个 token 实际使用的比例大约是 $K/N$。例如 $N=64$、$K=2$ 时，单个 token 只会进入约 $3.125%$ 的 Expert。需要注意的是，一个 batch 中不同 token 可能选择不同 Expert，因此从整个 batch 的角度看，很多甚至全部 Expert 都可能参与计算，只是每个 token 的路径仍然是稀疏的。

3. 数学视角：MoE 与普通 FFN 的关系

经典 MoE 可以写成：

$$
MoE(x)=\sum_{i\in TopK(x)}g_i(x)E_i(x)
$$

其中 $E_i(x)$ 是第 $i$ 个 Expert，$g_i(x)$ 是 Router 给这个 Expert 的权重，$TopK(x)$ 表示当前输入最终选择的 Expert 集合。假设 Top-2 得到 $g_2=0.7$、$g_5=0.3$，那么输出就是：

$$
y=0.7E_2(x)+0.3E_5(x)
$$

这个公式基本概括了经典稀疏 MoE 的核心：先根据输入决定计算哪些函数，再把这些函数的输出按路由权重组合起来。

3.1 多个 Expert 是否等价于一个更大的 FFN

如果所有 Expert 每次都参与计算，而且只是固定地把结果相加，那么它们确实可以等价成一个更宽的 FFN。以两个 Expert 为例：

$$
E_1(x)=W_2^{(1)}\sigma(W_1^{(1)}x),\qquad
E_2(x)=W_2^{(2)}\sigma(W_1^{(2)}x)
$$

如果总输出始终是 $E_1(x)+E_2(x)$，可以把第一层权重纵向拼接、第二层权重横向拼接：

$$
W_1=
\begin{bmatrix}
W_1^{(1)}\
W_1^{(2)}
\end{bmatrix},
\qquad
W_2=
\begin{bmatrix}
W_2^{(1)} & W_2^{(2)}
\end{bmatrix}
$$

这样就有 $W_2\sigma(W_1x)=E_1(x)+E_2(x)$。所以单纯把一个 FFN 拆成多个分支并不能体现 MoE 的本质；真正关键的是 Router 会根据输入改变计算路径。

对于 Top-1 MoE，可以把整个网络粗略理解为一个分段函数：

$$
f(x)=
\begin{cases}
E_1(x), & x\in R_1\
E_2(x), & x\in R_2\
E_3(x), & x\in R_3
\end{cases}
$$

这里的 $R_1,R_2,R_3$ 可以理解为 Router 在表示空间中划出的不同区域。不同输入落入不同区域，就会调用不同参数子网络。一个足够大的 Dense FFN 在函数逼近能力上可能逼近这样的映射，但它通常需要每次执行完整网络，而 MoE 可以只计算当前需要的部分。

3.2 为什么 MoE 能在增加参数量时控制计算量

假设共有 $N$ 个 Expert，每个 Expert 有大约 $P$ 个参数，那么 Expert 部分的总参数量约为 $NP$。如果每个 token 只选择 $K$ 个 Expert，则该 token 在 Expert 部分实际参与计算的参数量约为 $KP$。因此：

$$
\frac{P_{\text{active}}}{P_{\text{total}}}\approx\frac{K}{N}
$$

例如有 64 个 Expert、Top-2 routing，Expert 总容量约为 $64P$，但单个 token 的 Expert 计算只涉及约 $2P$。这也是 MoE 在大模型中最有吸引力的地方：可以明显扩大参数池，而不让每个 token 都计算全部参数。

不过这里不能简单把“active parameters 少”理解为“实际运行时间一定按同样比例下降”。真实系统还需要处理 Router、token 排序、数据搬运、跨卡通信和不规则矩阵计算，这些都会产生额外开销。因此 MoE 省的是主要的 Expert 矩阵乘法，而不是所有运行成本。

4. MoE 如何训练，以及 Expert 如何产生分工

MoE 的训练仍然依赖普通的反向传播，只不过不同 token 会经过不同 Expert，因此不同 Expert 会收到不同的梯度。假设某个 token 被路由到 $E_2$ 和 $E_4$，输出为 $y=g_2E_2(x)+g_4E_4(x)$，那么最终任务损失 $L$ 会对 $\theta_2$ 和 $\theta_4$ 产生梯度，而其他没有参与该 token 前向计算的 Expert 不会收到来自这个 token 的 Expert 梯度。

Expert 的分化通常从很小的随机差异开始。不同 Expert 独立初始化，Router 也有自己的随机初始化，因此训练早期某些 token 可能只是偶然更偏向某个 Expert。假设一类表示更频繁地被送给 $E_1$，那么 $E_1$ 会获得更多这类数据的梯度并逐渐更擅长处理它们；Router 又会发现把类似输入送给 $E_1$ 能得到更低的 loss，于是进一步强化这种路由偏好。这个过程可以看作 Router 与 Expert 的共同适应，而不是先人为规定“哪个 Expert 负责什么”。

4.1 Router 的梯度从哪里来

Router 自身也有可学习参数。虽然 Top-K 的索引选择是离散操作，本身不可直接求导，但被选中的 routing weight 仍然是连续变量。例如：

$$
y=g_2(x)E_2(x)+g_5(x)E_5(x)
$$

损失可以沿着 $L\rightarrow g_i(x)\rightarrow W_r$ 传播到 Router。实际实现中，通常把当前 forward 得到的 Top-K index 当作固定的路由结果，而对选中 Expert 的 routing weight 正常求导。不同 MoE 还会配合 noisy routing、router regularization 或其他辅助方法来提高训练稳定性。

4.2 为什么还需要 Load Balancing

如果只依赖任务损失，Router 很容易越来越偏向少数 Expert。某个 Expert 一旦在训练早期稍微占优，就会得到更多 token，随后得到更多训练信号，又进一步变强，最后可能出现大多数 token 都集中到少数 Expert 的情况。这通常被称为 Expert Collapse 或 Routing Collapse。

因此训练目标往往不是单独的任务损失，而是：

$$
L_{\text{total}}=L_{\text{task}}+\lambda L_{\text{balance}}
$$

$L_{\text{balance}}$ 用来约束 Expert 的使用分布，避免某些 Expert 长期过载、另一些 Expert 几乎没有数据。这里要区分“负载均衡”和“学到相同内容”：负载均衡只希望不同 Expert 获得相对合理的 token 数量，并不要求它们的输入分布或参数变得相同。

6. 计算、内存与 MoE 的适用范围

MoE 最容易被误解的一点是：稀疏计算并不意味着参数也被稀疏存储。如果模型有 64 个 Expert，即使某个 token 只使用其中两个，其余 62 个 Expert 仍然属于模型，它们的权重仍然要存储在某个 GPU、CPU 或其他设备中。因此 MoE 主要减少的是“当前 token 要做多少矩阵乘法”，而不是“模型一共要保存多少参数”。

训练时还需要考虑 gradient 和 optimizer state。一个 Expert 即使当前 batch 没有被某些 token 使用，它的参数和优化器状态通常仍然存在。因此大型 MoE 往往会配合 Expert Parallelism、ZeRO、optimizer sharding、CPU offload 等技术来降低单卡内存压力。

从性能上看，MoE 也不一定比 Dense 模型更快。减少 FLOPs 只是其中一部分，Router、token 重排、All-to-All 通信、内存访问和不规则的小矩阵计算都有成本。尤其在 batch 很小时，每个 Expert 可能只收到少量 token，GPU 很难形成足够大的矩阵乘法，硬件利用率反而可能下降。因此 MoE 通常更容易在大 batch、高吞吐和多设备训练中体现优势，而在小模型、低延迟或端侧场景中不一定划算。

MoE 的价值可以从两个方向理解。第一个方向是 Scaling，即通过大量 Expert 扩大模型总参数，同时让单个 token 只使用少数 Expert；第二个方向是 Specialization，即让不同输入使用不同参数空间。例如在 VLM 或 VLA 中，可以让 Vision、Language、Action 等不同模态使用不同 Expert，以减少参数竞争和梯度干扰。这里 MoE 的目的未必是扩参，而是让不同类型的信息拥有更合适的处理路径。

因此 MoE 并不是一种“越加越好”的万能模块。它更适合模型容量需求很大、训练数据充分、输入具有一定异质性，同时硬件能够承担额外存储和通信成本的场景。如果模型本身很小、数据有限、任务高度同质、batch 很小或者系统受内存和通信严重限制，Dense 结构往往更简单也更高效。

回到最核心的定义，MoE 可以理解为：模型内部存在多个可独立工作的子网络，Router 根据输入选择少量子网络参与计算，从而实现条件计算。 数学上最典型的形式仍然是：

$$
MoE(x)=\sum_{i\in TopK(x)}g_i(x)E_i(x)
$$

它带来的两个主要结果分别是：一方面，总参数容量和单次计算量不再严格绑定；另一方面，不同输入可以获得不同的参数和计算路径，这也正是 MoE 在大模型 Scaling 和多模态 Specialization 中都能发挥作用的原因。
